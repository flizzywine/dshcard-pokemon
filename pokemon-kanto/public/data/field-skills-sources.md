# Field skills and travel gates

The field-move badge mapping and party-member requirement are based on the **pret/pokefirered** source at fixed commit [`ce6406d8c2eaf46d543c8a2606de0c3cb1951982`](https://github.com/pret/pokefirered/tree/ce6406d8c2eaf46d543c8a2606de0c3cb1951982). These links intentionally pin the revision used for this implementation.

## Source evidence

- [`include/constants/party_menu.h`, lines 34–40](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/include/constants/party_menu.h#L34-L40) orders the field-move indices: Flash 0, Cut 1, Fly 2, Strength 3, Surf 4, then Rock Smash and Waterfall.
- [`src/party_menu.c`, lines 3925–3930](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/party_menu.c#L3925-L3930) rejects an HM field move unless `FLAG_BADGE01_GET + fieldMove` is set. The badge flags are sequential in [`include/constants/flags.h`, lines 1364–1371](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/include/constants/flags.h#L1364-L1371). Together with the game’s badge order, the five implemented gates are Flash/Boulder, Cut/Cascade, Fly/Thunder, Strength/Rainbow, and Surf/Soul.
- [`src/field_player_avatar.c`, lines 1184–1198](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/field_player_avatar.c#L1184-L1198) implements `PartyHasMonWithSurf` by searching the player’s party for a Pokémon that knows Surf. An HM item in the bag is therefore not a substitute for a party member that knows the move.
- [`src/field_control_avatar.c`, lines 601–606](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/field_control_avatar.c#L601-L606) gates the wild Surf prompt on Soul Badge, a party Surf user, and surfable water. [`src/party_menu.c`, lines 4061–4074](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/party_menu.c#L4061-L4074) also requires a Surf user and a valid water tile when Surf is selected.
- [`src/region_map.c`, lines 3558–3575](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/region_map.c#L3558-L3575) emits Fly icons for map sections whose status is `MAPSECTYPE_VISITED`; this supports restricting destinations to previously visited towns. [`src/party_menu.c`, lines 4099–4105](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/party_menu.c#L4099-L4105) also checks whether the current map permits Fly/Teleport.
- The supported adjacency and node kinds come from this project’s [`map.json`](./map.json), rather than from a copied or expanded cartridge map. In particular, only its existing Route 19–21, Seafoam, Cinnabar and Route 16–18 nodes receive these gates; no Sevii Islands are added.

## Implemented interpretation and limits

`field-skills.cjs` checks for a currently present party member that has the relevant move ID, plus the named badge gate. It does not teach moves, grant badges, or mutate a save. Cut and Strength are reported as contextual actions because the current map data does not model obstacle coordinates. Flash is exposed as optional lighting for Rock Tunnel and Seafoam, and never blocks travel: this project has no dark-tile visibility system to reproduce the cartridge’s visual effect.

Surf is required on first entry to an unvisited water-corridor edge. Previously visited adjacent nodes are allowed as legacy return edges; when the current island/water node is an older save location, the module also permits the next edge along a map path to another historically visited town. A traveler already on a water corridor may always return to an adjacent town. These return allowances do not grant Surf or a badge. Fly is a separate operation and does not bypass adjacency in `validateTravel`; it requires Fly, the Thunder Badge, a visited town destination, and a non-cave/non-Safari current node.

The Route 16–18 Bicycle rule is applied as the requested project travel gate, recognizing the story flag `剧情.关都事件.标记.bicycle` or a Bicycle key-item entry. The node graph does not encode gates for Cut/Strength obstacles, indoor maps, Fly-permitted map types, water tiles, or exact visual darkness. `validateTravel` therefore handles only the modeled map-edge rules; these contextual field-move effects still need explicit world/map interaction data before they can match cartridge tile behavior exactly.
