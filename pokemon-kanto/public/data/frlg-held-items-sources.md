# FRLG wild held items and battle held-item effects

Source revision: [`pret/pokefirered` `ce6406d8c2eaf46d543c8a2606de0c3cb1951982`](https://github.com/pret/pokefirered/tree/ce6406d8c2eaf46d543c8a2606de0c3cb1951982).

- `frlg-held-items.json` transcribes `src/data/pokemon/species_info.h` `itemCommon` and `itemRare` for original Kanto species 1–151. Wild generation is implemented from `src/pokemon.c` `SetWildMonHeldItem`: ordinary wild battles only; if common and rare are the same, that item is guaranteed; otherwise `Random() % 100` values 45–94 select common, 95–99 select rare, and 0–44 leave the slot empty. The project derives that draw from the encounter UID hash so restoring/retrying an already persisted encounter cannot reroll its item. The source PRNG sequence itself is not reproduced.
- `src/battle_main.c` calls `SetWildMonHeldItem()` when creating the encounter party and excludes trainer/Poké Dude/legendary battles. Current integration generates only when `makeMon(..., {wild:true})` is used; fixed legendary encounters and trainers therefore stay itemless.
- `src/battle_script_commands.c` `Cmd_getexp` first divides the base award by participants (or applies Exp. Share), then multiplies a holder's earned share by 150/100 for Lucky Egg and, in trainer battles, by 150/100 again. Integer division occurs at each step. This implementation applies Lucky Egg to the per-defeated-foe EXP amount the Pokémon actually earns, with integer floors; non-participants without Exp. Share still receive nothing. The project's optional journey-wide EXP rule remains a project-specific rule, and its resulting recipients can also benefit from a Lucky Egg.
- `src/battle_util.c` activates `moneyMultiplier = 2` on switch-in for `HOLD_EFFECT_DOUBLE_PRIZE`; `src/data/items.json` identifies Amulet Coin as that effect and describes the holder taking part. The local adapter activates the multiplier when a living holder is active at battle start or during a player action. Activation is battle-wide once triggered. Existing trainer-prize settlement consumes that multiplier, and wild battles still award no trainer prize.
- The item is legitimately obtainable from the Oak aide at the Route 16 North Entrance 2F: pinned source `data/maps/Route16_NorthEntrance_2F/scripts.inc` defines `REQUIRED_CAUGHT_MONS, 40`, calls `GetPokedexCount`, and gates on `VAR_0x8006`, the caught count. `src/prof_pc.c` shows that `GetPokedexCount` returns Kanto seen count in `VAR_0x8005` and caught count in `VAR_0x8006` for this mode; `src/pokedex.c` confirms case 1 counts `FLAG_GET_CAUGHT`. The aide checks item space, awards `ITEM_AMULET_COIN`, then sets the one-time claim flag `FLAG_GOT_AMULET_COIN_FROM_OAKS_AIDE`. The native machine-acquisition adapter exposes that reward at the matching `route16` map node after 40 caught species.
- Captured wild Pokémon keep the remaining held item through the existing `updateMon`/capture snapshot path. Showdown's Gen III battle state remains authoritative for consumption or theft; the post-battle sync stores both sides' resulting item IDs. No stolen item is additionally copied to the bag, preventing duplicate ownership.

Coverage is intentionally bounded to the current 151-species Kanto encounter model and single-opponent battle adapter. Original cartridge RNG state, link/safari/trainer-tower modes, mid-battle level-up timing, Pickup, and physical item retrieval after fainting are not claimed as replicated. Species whose held item is not in the local item catalog remain in the source table but are not generated; every nonempty held item used by the current Kanto wild pools has a catalog entry.
