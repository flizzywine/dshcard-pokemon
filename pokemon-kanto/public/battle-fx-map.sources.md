# Battle effect mapping notes

`battle-fx-map.js` keys effects by the normalized Gen III move id. Move number, generation, type, category, target, flags, and multihit behavior come from the bundled Showdown `Dex.mod('gen3')` move data. `catalog.moves` includes every numbered move 1–354, deduplicated by move id (Hidden Power has multiple type aliases sharing number 237). `catalog.species[*].moves` continues to come only from the Kanto species' legal Gen III learnsets, so the larger event/display catalogue does not make those moves selectable.

The bundled Showdown base Metronome implementation selects from the active generation's move dex by `move.flags.metronome` (in `vendor/showdown/data/moves.js`); the Gen III mod supplies overrides to those flags in `vendor/showdown/data/mods/gen3/moves.js`. The catalogue copies that flag from `Dex.mod('gen3')` and does not maintain a separate Metronome ban list. A deterministic KantoGame test invokes Metronome and observes the non-Kanto `Sacred Fire` event.

The named stage cues in `stageCues` are presentation labels authored for this project; they do not alter move rules or infer extra hits. Distinct metadata cues cover signature moves and state moves including Hypnosis, Dream Eater, Leech Seed, Double Team, Substitute, Teleport, Transform, Hyper Beam, and Metronome.

The eight move presentations use the event sequence already emitted by the Gen III battle protocol: Hypnosis confirmation waits for `-status slp`; Dream Eater target effects wait for direct `-damage` and drain return waits for `[from] drain` healing; Double Team waits for an evasion `-boost`; Substitute waits for `-start`; Teleport waits for a successful `run` or a switch event; Transform waits for `-transform`; Hyper Beam charge starts on its `move` event and recharge follows `-mustrecharge`; Metronome release waits for the called move event carrying `[from] Metronome`. Misses, Protect, immunity, and failures show only actor windups.

`app.js` follows battle protocol events for resolution. A miss, immunity, failure, or a target protected by Protect receives no target impact effect. Damage confirmation drives the brief hit flash, HP update, and stage pulse. Multi-hit count text uses the protocol count and the animation does not add hits. Capture success requires both a caught record and an ended snapshot; the reported three visible shakes can still end in a break-free.

The choreography and CSS are original stage effects inspired by the move concepts and familiar FireRed/LeafGreen battle pacing. They are not frame-by-frame recreations and use no copied game screenshots or sprites in these added effects.

The battle renderer gives more than twenty signature moves separate authored stage paths: for example Surf sweeps a wave front, Hydro Pump charges a focused jet, Thunder uses a single storm bolt, Thunderbolt uses a single bolt, Aurora Beam draws a prismatic ribbon, Blizzard scatters a broad flurry, Magical Leaf homes leaf shapes along individual paths, and Rock Throw/Rock Tomb launch a small/clustered stone volley. Earthquake uses arena fault marks; Rock Slide drops stones from overhead. These are visual signatures, not extra hits or altered move data. Status-category moves now keep miss/protect/fail presentation on the acting sprite; target-side status pulses only play when the event inspection confirms an effect. Damage and target impact effects remain tied to protocol outcomes and actual direct damage. All added FX use the existing fixed effect layer, have pointer-events disabled, derive their durations from the battle speed control, and are skipped in reduced-effects mode.

The shared presentation-skip control releases pending local waits, retains all remaining event log entries, and does not call the battle action endpoint again. The final authoritative snapshot restores status and side-condition labels after skipping or reloading. Delayed Earthquake camera callbacks carry a presentation serial so a skipped round cannot shake a later round.
